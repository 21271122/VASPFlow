# VASPFlow 内容策略

> 版本：v1.0（2026-09-03）
> 定位：让"用 AI 管理第一性原理计算"这件事，在中文计算材料/催化社区里形成清晰认知，并持续转化为 VASPFlow 的用户与贡献者。

---

## 一、现状与核心判断

**产品现状**：VASPFlow = DSH 插件 + vasp Agent 预设，覆盖 VASP 计算的扫描、可视化、批量构建、校验、AI 分析全链路。功能完整度高（9 个 Agent 工具、批次一致性校验、SD 差异反馈），但缺乏系统性的对外内容输出——GitHub README 是目前唯一的"内容"。

**核心判断**：

1. **赛道正处在窗口期**。AI for Science 是当前科研社区最热的话题，而"LLM + VASP 工作流"的成熟开源产品在中文社区几乎空白。先发声者定义品类。
2. **最大的内容资产不是功能列表，而是真实的科研工作流痛点**。仓库里那份《VASPFlow 插件问题与工具化建议》记录的 26 任务 d 扫描踩坑（SD 旗标被无感知改写、批次一致性、POTCAR 顺序校验），每一个都是研究生真实掉过的坑——这就是内容金矿。
3. **目标用户高度垂直且集中**，不需要大众传播，需要的是在正确的小圈子（计算催化/材料模拟课题组）里建立"专业、可信、真的好用"的口碑。

## 二、目标受众画像

| 画像 | 特征 | 核心痛点 | 内容偏好 |
|------|------|----------|----------|
| **A. 研究生/博士生（主力）** | 课题组批量算 DFT，会写脚本但水平参差 | 手动管几十个任务目录、INCAR 抄模板不知道对不对、收敛判断靠肉眼、审稿前整理数据痛苦 | 实操教程、踩坑实录、"5 分钟搞定 XX" |
| **B. 博士后/青年研究员** | 独立带课题，追求效率和方法论 | 工作流可复现性、批量任务的物理一致性（一条 E(d) 曲线各点约束不一致就废了） | 深度方法论文章、工具横评、工作流设计 |
| **C. 课题组导师/PI** | 不亲自算，但决定课题组用什么工具 | 学生算错的隐性成本、课题组方法标准化 | 短平快的价值陈述、案例、学生效率提升数据 |
| **D. 工具开发者/贡献者** | 会写代码，关注 AI Agent 工具链 | DSH 插件机制、Agent 工具设计模式 | 技术架构文章、设计决策解析 |

优先级：**A > B > D > C**。A 是传播节点（转发到课题组群），B 是口碑背书，D 决定生态，C 决定课题组级采用。

## 三、内容定位与差异化

**一句话定位**：

> "把 VASP 计算从'手动搬砖'变成'和 AI 对话'——每一个功能背后都是一个真实的科研踩坑。"

**差异化三支柱**（竞品/平替内容普遍缺这三样）：

1. **真实案例驱动**，不是功能演示，而是"我这个 26 任务的真实课题，AI 怎么帮我构建、校验、抓出批次不一致"；
2. **确定性优先的技术叙事**——"SD 旗标绝不按元素序推断、POTCAR 等长同序才放行"，科研用户最怕 AI 瞎猜，这一点要反复讲、当卖点讲；
3. **踩坑的透明度**——连自己的 bug 清单（P1–P6）都公开写出来，这种坦诚在科研工具圈极其稀缺，是信任的加速器。

**品牌声音**：科研同行，不是营销号。允许出现具体参数、具体报错信息、具体文件名。宁可长一点，也不空洞。

## 四、内容支柱（Content Pillars）

| 支柱 | 占比 | 内容方向 | 对应受众 | 转化目标 |
|------|------|----------|----------|----------|
| **P1 科研工作流实战** | 35% | d 扫描批量构建全流程、ZPE 频率计算、收敛判断、审稿数据整理 | A/B | 安装使用 |
| **P2 AI×计算化学方法论** | 25% | Agent 工具该做什么/不该做什么（确定性 vs 猜测）、人机分工设计、DSH 插件架构 | B/D | 建立"专业"认知 |
| **P3 新手友好教程** | 20% | INCAR 关键参数、SD 旗标是什么、POTCAR 顺序为什么重要、K 点选择 | A | 引流+涨粉 |
| **P4 产品与更新** | 10% | 版本发布、新功能、roadmap | 全部 | 留存 |
| **P5 踩坑与开放记录** | 10% | 真实 bug 复盘（如 P6 template 崩溃修复记）、社区问题解答 | B/D | 信任建设 |

**铁律**：P5 是本项目的独门武器，坚持做。每修一个值得说的 bug，就发一篇复盘。

## 五、平台策略

| 平台 | 角色 | 内容形态 | 频率 |
|------|------|----------|------|
| **知乎** | 深度内容主阵地 | 2000–4000 字长文（P1/P2/P5），回答"VASP 批量计算""INCAR 怎么写"等高流量问题 | 2 篇/月 |
| **B站** | 演示与破圈 | 3–8 分钟录屏：面板操作、3D 结构旋转、Agent 对话实况；"AI 帮我建 26 个 VASP 任务"这类标题 | 1–2 条/月 |
| **微信公众号** | 私域沉淀与教程库 | 知乎/B站内容的重排版 + 教程系列连载（可做成合集菜单） | 1 篇/周（含转载自知乎） |
| **GitHub** | 转化终点 | README 优化（加 GIF 演示）、awesome-list 提交、Discussion 区运营 | 持续 |
| **小红书** | 意外流量池 | "博士生科研神器""DFT 打工人日常"轻内容，导流公众号 | 2 条/月，试水 |
| **X（英文）** | 国际社区 | #AIforScience #DFT 话题，截图 + 短视频，链接 GitHub | 2–3 条/月 |

**核心策略**：知乎/B站原创 → 公众号沉淀 → GitHub 转化。小红书和 X 是低成本试验田，跑不出数据就砍。

## 七、内容再利用（一鱼多吃）

每个"大内容"拆出至少 4 个衍生品：

```
一篇深度长文（如 26 任务实战）
├── B站录屏（实操过程本身）
├── 3–5 张小红书/朋友圈图（数据对比图："手工 3 小时 vs AI 10 分钟"）
├── 1 条 X 推文（截图 + 一句话 + GitHub 链接）
├── README 的案例展示段落
└── 下一篇文章的引子（文末埋钩子）
```

**立即可做的低成本素材**：把《VASPFlow 插件问题与工具化建议.md》里 P1–P6 逐条拆成"科研计算翻坑系列"，这是已经写好的内容，只需重构成叙事。

## 八、指标体系（前 3 个月）

| 层级 | 指标 | 3 个月目标 |
|------|------|-----------|
| 曝光 | 知乎总阅读 / B站播放 | 10,000+ / 5,000+ |

| 深度转化 | 提 issue / Discussion 提问 / 私信咨询 | ≥15 个真实用户反馈 |

**判断标准**：前 3 个月看"收藏率 + issue 数"，不看粉丝量。科研工具的传播是窄而深的，一个课题组内的口碑传播胜过一万泛粉。

## 九、执行建议

1. **单人可跑**：按上述日历，每周投入约 4–6 小时即可维持节奏。忙的周砍小红书和 X，保知乎长文。
2. **先囤后发**：正式开始前先写好 3 篇存稿（W1 王牌文 + 2 篇教程），避免开局断更。
3. **每个功能更新都过一遍"能不能成为内容"**：版本发布不是新闻，"为什么这样设计"才是内容。
4. **建立选题池文件**（可放 `docs/content-ideas.md`）：日常踩坑、用户提问、社区热点随手记，每月清点一次。
5. **3 个月后复盘**：按第八节指标决定平台取舍和支柱比例调整。
